1. Nutzer-Login & Datenbankstruktur

• Beim Start der App erscheint ein Login-Fenster: Nutzer gibt Benutzername/Passwort ein.

• Die Datenbank enthält eine Tabelle users, in der Konten mit gehashten Passwörtern und API-Infos gespeichert werden:

• id, username, password_hash, api_key_gmail, api_key_outlook, …

• Nach erfolgreichem Login wird der Zugriff auf die App und somit die Verbindung zwischen MailAPI und SQLite hergestellt

• Vorteil: Mehrere Nutzer können die App verwenden, ohne gleichzeitig aktiv zu sein.

      •jeder User kann später kurze Notizen hinter die angezeigten Mails für andere User hinterlassen
2. Eingang der E-Mails

• Nach Login verbindet sich die App mit den API-Daten des eingeloggten Nutzers (z. B. Gmail, Outlook, GMX).

• Beim Start werden neue, ungelesene Mails abgerufen und mit Zeitstempel in die SQLite-Datenbank eingetragen.

• Bereits gespeicherte Mails werden nicht doppelt eingetragen.

• Jede Mail wird in ihre Bestandteile zerlegt:

• Absender, Betreff, Inhalt, Datum, user_id.

• Ergebnis: Die Datenbank enthält alle Mails, alt und neu, übersichtlich geordnet pro Nutzer.
3. Regeln/Schlüsselbegriffe

• Regeln werden in einer eigenen Tabelle rules gespeichert.

• Nutzer kann Regeln im UI anlegen, z. B.:

• keyword: Umsatz, operator: >, value: 1000

• keyword: garantiert, operator: contains

• Beim Abrufen von Mails prüft die App den Inhalt gegen diese Regeln.
4. Erkennung in der E-Mail

• App sucht nach Schlüsselwörtern und Werten in der Mail.

• Beispiel:

• Mail: „Wir machen für Sie mindestens 1.500 € Umsatz pro Woche.“

• Regel: Umsatz > 1000 → Treffer: Umsatz = 1500.

• Treffer werden in der Tabelle matches gespeichert, sodass du später Statistiken ziehen kannst.
5. Übersicht im Interface (tkinter)

• Hauptfenster zeigt:

• Liste aller Mails (nur für eingeloggten Nutzer)

• Absender, Betreff, Datum, Bewertung, erkannte Keywords

• Optionaler Filter: Nur ungelesene Mails, nur Mails mit Treffern, etc.
6. Bewertung / Entscheidung

• Jede Mail bekommt einen Score anhand der erkannten Begriffe:

• Positive Punkte für gute Treffer (z. B. Umsatz hoch)

• Negative Punkte für „Warnbegriffe“ (100% garantiert, „schnell reich“)

• Entscheidung:

• Interessant → mögliche Antwort

• Neutral → höfliche Absage

• Uninteressant → ignorieren

• Priorisierung: Antworten immer innerhalb von 72 Stunden, aber Firmen mit mehr positiven Faktoren bekommen Vorrang.
7. Manuelle Bewertung

• Nach dem Lesen kann der Nutzer eine Bewertung von 1–10 vergeben.

• Diese Bewertung wird gespeichert, um Statistiken oder spätere AI-Analysen vorzubereiten.
8. Automatische Antwort

• Optional kann die App automatisch antworten:

• Interessant → neutrale Nachfrage

• Neutral → höfliche Absage

• Uninteressant → Standardabsage oder keine Antwort

• Texte der Antworten werden in einer templates-Tabelle gespeichert und können angepasst werden.
9. Anpassbarkeit

• Nutzer kann im UI:

• Regeln hinzufügen/ändern/löschen

• Antwortvorlagen ändern

• API-Zugangsdaten aktualisieren

• Schlüsselwörter dynamisch verwalten
10. Erweiterungen (für später)

• AI-Analyse: App erkennt umformulierte Begriffe (z. B. „über tausend Euro Gewinn“).

• Lernsystem: Automatisches Lernen aus Nutzerentscheidungen.

• Blacklist/Whitelist:

• Blockierte Absender werden ignoriert

• Vertraute Kontakte werden nicht gefiltert

• Word-Dokument-Export: Analyse von Häufigkeit und Qualität guter Mails.
11. Technische Basis

• Programmiersprache: Python 3.9

• Datenbank: SQLite (lokale Datei coldresponse.db)

• Tabellen: users, emails, rules, matches, templates

• UI: tkinter (lokales Desktop-Interface)

• API-Zugriff: Gmail/Outlook IMAP oder API (kostenlos im Entwicklerkonto)

• Architektur:

• Single-User-Modus pro Session (kein gleichzeitiger Zugriff)

• Mehrere Nutzerkonten, getrennte Datensätze

• Beim Start: Sync neuer Mails → Anzeige aller Mails des Nutzers
